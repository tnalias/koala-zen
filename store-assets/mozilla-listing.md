## 5. Privacy & permissions

### Data collection (AMO submission questionnaire)
**Updated 2026-09-29, current state (this replaces the kDrive and shared-token parts of the notes below).** The kDrive backup, the restore from kDrive and the daily automatic kDrive backup are removed; backup is a local `.json` file the user exports and imports manually. `manifest.json`'s `data_collection_permissions` is unchanged (`required: ["none"]`, `optional: ["authenticationInfo", "personallyIdentifyingInfo"]`): the optional part now covers only the user's own Infomaniak tokens and, for the email warning, the attendee addresses the message is sent to.

Answer: **By default, this add-on does NOT collect or transmit any user data and makes no network requests.** It has no analytics, no account and no server of its own, and it never uploads the user's data to any cloud. Only two optional features, both off by default, contact the network, and only the user's own Infomaniak account, with personal tokens the user creates in the Infomaniak Manager and pastes:
- **Infomaniak Calendar** (`api.infomaniak.com`), with a token limited to the single `workspace:calendar` scope: reads the events of the calendars the user ticked, as described in the 2026-09-16 note below.
- **Notify attendees by email** and **Count my emails** (`mail.infomaniak.com`, plus `api.infomaniak.com` for the sending address's signature), with a second token limited to the single `workspace:mail` scope: as described in the 2026-09-22 and 2026-09-26 notes below. The attendees of the event are read with the calendar token.

There is no shared token anymore. When a token is pasted, the add-on makes read-only probe calls and refuses a token that also opens the other Koala Zen use or kDrive (error `too_broad`); scopes Koala Zen never calls cannot be detected, so the user is told to tick a single scope. On update, tokens stored under the old instructions (several scopes on one token) are forgotten, the old encryption key JWK in `storage.local` and all kDrive settings are deleted, and the selected calendars and mailbox are kept; the Calendar card explains why and asks for new single-scope tokens.

Tokens are encrypted with AES-GCM 256. The key is a non-extractable `CryptoKey` stored in IndexedDB: no code, not even the extension's, can read its bytes; it is no longer next to the ciphertext in `storage.local` and never part of any export. Known limit: a program that reads the browser profile files on disk could still recover it; no OS keychain is available to an extension without a native helper app. "Erase everything" also deletes the key. Tokens leave the device only in the optional "Infomaniak connections" part of an exported file, encrypted with a passphrase of at least 12 characters (PBKDF2-SHA256, 600,000 iterations, then AES-GCM 256), never stored; files made before 2026-09-29 (v1) restore their settings but never their tokens.

### Permissions justification (for the AMO reviewer notes)
- **alarms**: schedule the periodic reminder at the interval you choose.
- **idle**: detect when you have stepped away from the keyboard, so the koala does not interrupt an empty desk. It only reads the active/idle/locked state, never what you are doing.
- **storage** and **unlimitedStorage**: save your settings and your custom images/quotes locally on your device. `unlimitedStorage` lets custom PNG images exceed the small default quota.
- **tabs**: read the URL of the *active* tab only, so the koala can appear on the current page and can be paused on video-call sites. It does not read your browsing history.
- **scripting**: display the koala on the current page (inject the animation) when needed.
- **Host permission (http/https, all sites)**: the koala can appear on any normal web page you are viewing. This access is also used to match the video-call domains, and to let the background script reach `api.infomaniak.com` and `mail.infomaniak.com` for the optional calendar connection and the optional email features (until 2026-09-29 it also served the optional kDrive backup, now removed). No page content is read, stored, or sent anywhere.
- **declarativeNetRequest** (new in 2.0.1, narrowed in 2.2.0, re-justified 2026-09-29): required only for the optional Infomaniak Calendar connection and the optional email features (Notify attendees, Count my emails). Firefox and Chrome both add an `Origin` header to cross-origin requests from an extension, which the Infomaniak API rejects with a silent redirect. Two session rules (one per host), installed by the background script at startup, strip that one header on requests to `api.infomaniak.com` and `mail.infomaniak.com` that come from the extension itself (no tab, `tabIds: [-1]`, i.e. the background's own requests). Requests made by web pages, including Infomaniak's own tools open in a tab, are never modified. The rules do not block or redirect anything, and they have no effect unless the user has connected a calendar or a mailbox. Until 2.2.0 the rule was static and applied to every tab's requests to that API, which broke Infomaniak's Newsletter tool; this is fixed. **Corrected 2026-09-29:** the kDrive backup that this permission also served until then is removed, so kDrive is no longer part of its justification.
- **notifications** (new in 2.2.0): used for one thing only, the optional heads-up three minutes before a calendar meeting, and only when no http(s) page is in front to show the in-page bubble instead. The notification carries the meeting title and time, and clicking it opens the meeting's video link if there is one. Nothing is shown unless the user has connected a calendar and left "Warn me 3 min before" on.

### Security hardening (added 2026-09-29, for the reviewer)
- **Tokens**: two separate tokens, each limited to one scope (`workspace:calendar` for the calendar, `workspace:mail` for email); read-only probe calls refuse a pasted token that also opens the other use or kDrive (`too_broad`). Encrypted with AES-GCM 256 under a non-extractable `CryptoKey` stored in IndexedDB, never next to the ciphertext in `storage.local` and never exported; "Erase everything" deletes it. Tokens stored under the old multi-scope instructions are forgotten on update, and the old key JWK in `storage.local` is deleted.
- **Exported connections**: passphrase of at least 12 characters (was 4), PBKDF2-SHA256 with 600,000 iterations (was 200,000), then AES-GCM 256; the passphrase is never stored. v1 files restore their settings, never their tokens.
- **On-page bubbles**: `content.js` and `passages.js` render in a **closed** shadow DOM, so the page's own scripts cannot read the meeting title or attendee addresses, rewrite the message or click Send. The Send and "Join the video call" buttons act only on trusted events (`isTrusted`). Before sending, the background re-reads the event's attendees and refuses the whole send if any recipient is not an invitee (`bad_recipients`).
- **Vault and send nonces (2026-10-06, ECC review)**: sensitive keys (meeting cache and state, identity, calendars, mailbox, sent log, rate log, nonces, encrypted tokens) are stored in an extension-origin IndexedDB store, not in `storage.local` (which content scripts can read and write). `kz-notify-prepare`/`kz-notify-send` from a content script require a one-time nonce delivered with the meeting bubble, bound to the tab, event and its end time; the subject is built by the background (the reviewed body comes from the bubble, HTML-escaped); a lock and a 6-per-hour quota apply. Send/Join require `isTrusted`, a visible host (no opacity, filter, clip-path or transform on the top-layer host, locked with `!important`) and at least 500 ms on screen; synthetic Escape is ignored. Scope probes fail closed and re-run on import; `redirect: "manual"`; the DNR session rule now only targets `mail.infomaniak.com/api/` with `tabIds: [-1]` (the calendar API no longer has one).
- **Closed list of API calls**: `ikFetch` refuses, before any network access, every call that is not one of the eleven the add-on needs (method, host and path shape; no `..` or encoded slashes). Infomaniak scopes are broad (event write/delete, contacts, mail delete/move), so this keeps a hijacked add-on from using a token for anything else.
- **Messaging**: the background accepts only four message types from content scripts (`kz-outcome`, `kz-notify-prepare`, `kz-notify-send`, `kz-open-url`); everything else (tokens, connections, settings, backups) is accepted only from extension pages.
